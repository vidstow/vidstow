Review of the p2 prototype — second pass

Orange marks the current prototype Green marks the proposed change

This pass is written against p2.html as it stands after the dock v2 rework. Since the first review, p2 landed the scope fork for watch URLs with a list id, the reversible swap line, Change plus a folder popover on the dock, per-episode selection with All / None / Range, and the batch coverage line inline. Those are off the list. What is left is ordered by user harm, not by screen: trust bugs first, then the commit path, then honesty of numbers, then polish.

  • Scope fork + swap line
  • Change… and folder picker on the dock
  • Per-episode selection · All / None / Range
  • Batch coverage, 4 of 5 reach it
  • Remaining-work queue · live status bar

Landed since the first review

A watch URL with a list id now stops at This link includes a playlist before anything is committed, with keyboard nav, and the dock carries a swap line so the choice stays reversible. The dock footer has Change next to the path, with a real folder popover. Playlist episodes are individually selectable, and a range form picks runs like 5–11. The batch dock shows total size and coverage inline. The [object Object] MB history row is fixed.

The v2 dock also moved the primary action into the right column for videos and batches, next to the format chips. That part created the problem in section 3.

Still open

Two trust bugs: the inspector can still describe a finished standalone job with Pause armed, and Cancel on a collection still deletes every remaining episode with one click and no confirm. On the commit path, the playlist Download button disappears entirely while the episode list is open, and the field's Analyze button still commits while labeled Analyze. The analysis itself is fragile: one keystroke destroys it.

Then honesty of numbers — playlist total, per-episode sizes and caps, the video plan list that v2 dropped — recognition support for episode selection, and the two product asks from the first pass, which nothing in the update previews: which surface owns per-item control, and what the badge counts.

1. The inspector still haunts finished standalone jobs

The first review filed this as a trust bug: the inspector must never describe a row that has left the list. The fix landed for collections — when the last child finishes, the collection is removed and selection falls through to the next row. Standalone jobs did not get the same treatment.

A finished standalone job keeps phase: 'done' in state.jobs forever. The queue renders rows without it, but the selection validator only checks that the job still exists — and it does. So the row disappears, the inspector keeps the job at 100%, and Pause stays armed as the primary button on a file that already moved to Downloads. Same bug, different path.

The rule is unchanged: done is a departure. Either the validator rejects done jobs when choosing what to keep selected, or finishing removes the job the way cancelling a collection removes its children. One line either way.

2. Cancel collection deletes work with one click

Cancel on a collection removes every unfinished child immediately. A 24-episode playlist at 12/24 loses twelve queued jobs on one click, with no confirm and no undo. The single-job Cancel is the same one click, but the stakes are one file; the collection case is where the confirm earns its keep.

This was a bullet in the first review's keep list. It is a section now because everything else around collections got more capable — per-episode selection, ranges, pause collection — while the destruction path stayed weightless. The more a collection holds, the more the confirm matters.

3. The commit must exist while you are choosing

Three problems on the commit path, one per dock shape.

The playlist commit blinks out

When the episode list is open, the playlist dock renders no Download button at all — the footer holds only Change and the path, and the right column has no action. The one moment you need the button, while you are picking episodes, is the one moment it does not exist. You select a range, look for the commit, and have to collapse the list to get it back. The button should live where the count is: in the episode header, with the live selection total.

Analyze that is not Analyze

In the result phase, the field's white Analyze button is dimmed but still fires the commit. Dimmed reads as disabled; it is not. Someone who pastes, waits, and clicks Analyze again — a reasonable "re-check this" — starts a download instead. In the result phase the button should either say what it does or be inert.

Three verbs for one act

A single video says Add to Queue. A playlist says Download 24. A batch says Admit 5. Admit is still engine language. One verb: Download for a single video, Download N for playlists and batches.

4. The analysis should survive a keystroke

Right now the analysis result is the most fragile object in the app. The field's input handler resets the phase to empty on any edit — one stray character and a 24-episode analysis is gone, no undo. Escape clears the result and the URL in a single press. And the error card still ends with "Paste another link to continue" while paste appends to the dead URL, because nothing selects it.

The recovery primitives already exist. ⌘L focuses the field and selects the text — the paste-replaces rule is built, it is just invisible. What is missing is wiring them to the moments that need them.

Three rules

Editing marks stale, it does not destroy. When the field changes and a result is showing, dim the dock and badge it Link changed — Analyze again. The old analysis stays readable until the new one replaces it. Escape is two-stage. First press dismisses the result and keeps the URL; second press clears the field. Error cards select the field. When a red card is showing, the URL text is selected, so the next paste replaces it — and the card's suggested action becomes a real button that does exactly that.

6. Numbers on the dock: sizes, caps, and the plan list

The batch dock is now the honest one — total size and 4 of 5 reach it, inline. The playlist and video docks are not.

Playlist: committed blind

The playlist dock says 24 episodes · up to 1080p. No total, no coverage, and episode rows carry only a duration. You are committing to gigabytes with no number anywhere. The batch code already computes exactly this; the playlist needs the same outcome line, and the episode rows need size and caps so deselecting episode 19 is a decision about 800 MB, not a guess.

Video: the plan comparison went away

V2 replaced the expandable plans list with one outcome line — MP4 · H.264 + AAC · 198 MB / Best available up to 1080p. Cleaner, but the size tradeoff between 1080p and 720p now costs one click per format, and the comparison that used to be visible is gone. Keep the compact default; restore the list behind the same disclosure that the playlist uses for episodes.

Scope dialog: the number is computed and never shown

The playlist card in This link includes a playlist shows 24 videos and a duration. The code computes the playlist's total size and does not render it. The video card shows its size. One side of the trade has a number; the other does not.

7. Thumbnails in the playlist review list

The episode list's one job is selection, and selection runs on recognition. Real playlist titles are often positional — 03 Mutexes, Lecture 7 — while the user's memory of that playlist is visual, built on YouTube, where thumbnails dominate. Twenty-four similar title strings are a parsing task. Thumbnails turn it into a recognition task. Every other list in the app already shows them — queue child rows, Downloads rows, the dock — and the review list, where the choices are actually made, is the only one without.

Two selection modes, one staging plan

Positional selection — take 5 through 11 — is served by the range form and wants dense rows. Recognition selection — skip what I have already watched — wants pictures. Row thumbnails cost roughly 10px of height each, a cost both modes pay, so they land only once the list has height to spend (section 5). The hover preview costs nothing and ships first.

Stage 1 — the dock previews the inspected episode

Hover or focus any row and the dock's 200px thumbnail swaps to that episode, with its title and numbers underneath. No layout change, works for a 500-item playlist, and it makes an existing element do new work instead of adding a new one.

Stage 2 — thumbnails on rows, with the pinned composer

Once the composer pins and the episode list takes the pane's height, rows gain thumbnails at the queue's child-row size — 34×20px — desaturated until the row is selected, so two dozen colorful tiles do not turn the pane into noise. The checkbox state becomes a visual layer.

Details that decide quality

Shorts carry 9:16 thumbnails: letterbox them or give verticals a narrower slot — a 16:9 crop is mush. Fetch progressively, so titles render first and thumbnails pop into fixed-size placeholders without shifting the list. A toggleable YouTube-style grid mode is rejected: it duplicates a layout for a benefit these two stages already cover, and it is hostile to range selection.

9. Search, grouping, and the Downloads badge

Carried over unchanged, minus one fixed bug. The [object Object] MB history row is gone.

Search

Search is still substring over title plus channel. Typing raft still matches most of a TechCraft library because raft sits inside TechCraft. Title and channel need token or word-boundary matching, with ranking, so a three-letter needle cannot empty the meaning of a channel name.

Playlist files

Playlist episodes still land as a flat pile next to one-off files, with no parent. The date groups — Today / Yesterday / Earlier — are right. Group the collection as one row that expands, the same way the queue groups it, whatever surface you pick below.

Badge

The Downloads badge still uses the accent "new" pill. A library count is not news; the quiet style with the pulse-on-increment that Queue already has is the right pattern. Remove and Delete file stay behind a click, not on the row.

10. Per-item control for playlist episodes — still the product fork

Nothing in the latest update previews an answer, so the fork from the first review stands. The prototype still shows one collection row with a 24 badge; the inspector still shows two live children and three waiting as a summary. You cannot pause episode 7, retry one failure, or see which of the remaining twelve will 429. The Queue badge still counts unfinished children while the list shows parents, and standalone jobs still wait at waiting · slot behind a collection that occupies both slots.

That last part is engine policy, not surface. Whatever surface you pick, fairness needs a scheduling rule — round-robin across collections, or a per-collection concurrency cap. The two asks below are the UI decisions; the slot rule is the engine decision that makes either UI honest.

Which surface should own per-item pause, retry, and cancel?

Unchanged from the first pass. Expanding children in the list makes episodes first-class rows. Treating the inspector as a child queue keeps the list dense and puts the work in the detail pane. Pick one, or describe a third.

What should the Queue badge count?

Still open, unchanged. After starting the playlist, the sidebar counts unfinished children while the list shows parents. Those two numbers cannot both be the user's model. Pick the count that matches the surface you chose above.

What to keep

The empty Home landing, the paste that decides the mode, the scope fork with the swap line, the folder popover on the dock, per-episode selection with All / None / Range, and the batch coverage line are the product. Remaining-work queue, live status bar, Settings colophon, and folding About into Settings are the chrome to keep. The 429 inspector with Retry, Cancel, and Copy details is still the right pattern for a single failed job.

One dead control survives from the first review: Confirm before starting downloads exists in Settings and commitAdd() still never reads it. Wire it or delete it. A dead control is worse than omitting the preference.

  • The scope fork and the swap line stay. Enter defaulting to Video is right — the URL names a video. Show the total on the playlist card, and make Esc keep the URL.
  • The current sidebar set stays, with the queue badge pulse. Keyboard shortcuts stay: ⌘L, ⌘1–3, ⌘,, ⌘F, Escape, and the scope-dialog arrows. Extend the same treatment to episode rows, which still have no keyboard path.
  • FFmpeg stays out of the sidebar. The quiet status-bar note on first merge is enough.
  • The range form's validation copy is good — inline, specific, no modal. Keep that pattern.
  • Episode thumbnails land in two stages: the dock hover preview first, row thumbnails when the composer pins. Desaturate until selected; letterbox Shorts.
  • Cancel collection gets the confirm from section 2 in whatever surface you pick above.
  • Cross-platform: VidStow ships on macOS, Linux, and Windows. The dock path, ⌘ hints, and Finder copy need Ctrl and Windows counterparts before this chrome is real.
